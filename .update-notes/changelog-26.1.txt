# Java Edition 26.1 – Datapack & Command Syntax Changes
# Relevant to: .mcfunction files, JSON data files, recipes, advancements, predicates, loot tables
# Source: https://minecraft.wiki/w/Java_Edition_26.1
# Released: March 24, 2026 | Data pack format: 101.1 | Resource pack format: 84.0

================================================================================
SECTION 1 – COMMAND FORMAT CHANGES
================================================================================

1.1  NEW COMMAND: /swing
  - Syntax: /swing <entity selector> <mainhand|offhand>
  - Both arguments optional (default: @s, mainhand)
  - Swings an entity's arm; returns count of entities swung.

1.2  /fetchprofile – new "entity" subcommand
  - Syntax: /fetchprofile entity <single entity selector>
  - Prints profile information (works for Players and Mannequins).

1.3  /time – now world-clock-based
  - A clock can be specified: /time of <clock> ...
  - If omitted, the dimension's default clock is used.
  - New subcommands:
      /time [of <clock>] set <time|timemarker>
      /time [of <clock>] add <time>          (negative values allowed)
      /time [of <clock>] pause
      /time [of <clock>] resume
      /time [of <clock>] query <timeline>
      /time [of <clock>] query <timeline> repetition
      /time [of <clock>] query time
      /time query gametime                   (unchanged, total world ticks)
      /time [of <clock>] rate <rate>         (float 0 < rate <= 1000)
  - Return value of "set" and "add" is now total elapsed clock ticks, not
    time-of-day. This affects /execute store results that capture /time output.
  - Available time markers for minecraft:overworld clock: day, noon, night, midnight

SECTION 2 – DATA PACK FORMAT (now 101.1)
================================================================================

2.1  pack.mcmeta
  - "pack_format" must be updated to 101 (integer) or "101.1" (string).

2.2  Villager inventory NBT path change
  - OLD: villager.*   (e.g. in /data get entity @e[type=villager,...] villager.Inventory)
  - NEW: mob.inventory.*
  - Any command using the "villager.*" NBT path for accessing villager inventory
    slots must be updated to "mob.inventory.*".

SECTION 3 – RECIPE CHANGES
================================================================================

3.1  "result" field now accepts short-form string
  - e.g. "result": "minecraft:foo"  is now valid (equivalent to {"id":"minecraft:foo","count":1})
  - smelting/blasting/smoking/campfire_cooking: "result" now also accepts "count" field.

3.2  minecraft:crafting_special_mapcloning REMOVED
  - Functionality absorbed by minecraft:crafting_transmute.
  - Any custom recipe using this type must be rewritten as crafting_transmute.

3.3  show_notification field added to more recipe types
  - Now valid on: crafting_shapeless, crafting_shaped, crafting_transmute,
    smelting, blasting, smoking, campfire_cooking, stonecutting,
    smithing_transform, smithing_trim.

3.4  Removed "group" field from recipes without a recipe book
  - Must be removed from: stonecutting, smithing_transform, smithing_trim.

3.5  Renamed stonecutter recipes (and related advancements)
  - minecraft:chiseled_stone_bricks_stone_from_stonecutting
      → minecraft:chiseled_stone_bricks_from_stone_stonecutting
  - minecraft:end_stone_brick_slab_from_end_stone_brick_stonecutting
      → minecraft:end_stone_brick_slab_from_end_stone_bricks_stonecutting
  - minecraft:end_stone_brick_stairs_from_end_stone_brick_stonecutting
      → minecraft:end_stone_brick_stairs_from_end_stone_bricks_stonecutting
  - minecraft:end_stone_brick_wall_from_end_stone_brick_stonecutting
      → minecraft:end_stone_brick_wall_from_end_stone_bricks_stonecutting
  - minecraft:mossy_stone_brick_slab_from_mossy_stone_brick_stonecutting
      → minecraft:mossy_stone_brick_slab_from_mossy_stone_bricks_stonecutting
  - minecraft:mossy_stone_brick_stairs_from_mossy_stone_brick_stonecutting
      → minecraft:mossy_stone_brick_stairs_from_mossy_stone_bricks_stonecutting
  - minecraft:mossy_stone_brick_wall_from_mossy_stone_brick_stonecutting
      → minecraft:mossy_stone_brick_wall_from_mossy_stone_bricks_stonecutting
  - minecraft:prismarine_brick_slab_from_prismarine_stonecutting
      → minecraft:prismarine_brick_slab_from_prismarine_bricks_stonecutting
  - minecraft:prismarine_brick_stairs_from_prismarine_stonecutting
      → minecraft:prismarine_brick_stairs_from_prismarine_bricks_stonecutting
  - minecraft:quartz_slab_from_stonecutting
      → minecraft:quartz_slab_from_quartz_block_stonecutting
  - minecraft:stone_brick_walls_from_stone_stonecutting
      → minecraft:stone_brick_wall_from_stone_stonecutting

3.6  minecraft:crafting_transmute changes
  - Can now accept multiple items for the "material" ingredient.
  - New optional fields:
      "material_count": integer range [1,8], default [1,1]
      "add_material_count_to_result": boolean, default false

3.7  minecraft:crafting_special_armordye RENAMED to minecraft:crafting_dye
  - New fields: "target" (ingredient), "dye" (ingredient), "result" (item stack),
    "category", "group", "show_notification"
  - The minecraft:dye component is required on matching dye items.

3.8  minecraft:crafting_special_tippedarrow RENAMED to minecraft:crafting_imbue
  - Copies minecraft:potion_contents from "source" to result.
  - New fields: "source", "material", "result", "category", "group", "show_notification"

3.9  minecraft:crafting_special_bannerduplicate changes
  - New fields: "banner" (ingredient), "result" (item stack)
  - "category" field removed.

3.10 minecraft:crafting_special_bookcloning changes
  - New fields: "source", "material", "allowed_generations" (int range [0,2], default [0,1]),
    "result"
  - "category" field removed.

3.11 minecraft:crafting_decorated_pot changes
  - New fields: "back", "left", "right", "front" (ingredients), "result"
  - "category" field removed.

3.12 minecraft:crafting_special_firework_rocket changes
  - New fields: "shell", "fuel", "star", "result"
  - "category" field removed.

3.13 minecraft:crafting_special_firework_star_fade changes
  - Now uses minecraft:dye component instead of hardcoded dye items.
  - New fields: "target", "dye", "result"
  - "category" field removed.

3.14 minecraft:crafting_special_firework_star changes
  - Now uses minecraft:dye component.
  - New fields: "trail", "twinkle", "fuel", "dye", "shapes" (map), "result"
  - "category" field removed.

3.15 minecraft:crafting_special_mapextending changes
  - New fields: "map", "material", "result"
  - "category" field removed.

3.16 minecraft:crafting_special_shielddecoration changes
  - New fields: "banner", "target", "result"
  - "category" field removed.

SECTION 4 – LOOT TABLE & LOOT FUNCTION CHANGES
================================================================================

4.1  NEW loot context: minecraft:villager_trade
  - Parameters: "this" (entity offering trade), "origin" (block position at feet)

4.2  NEW loot function: minecraft:set_random_dyes
  - Fields: "conditions", "number_of_dyes" (number provider)

4.3  NEW loot function: minecraft:set_random_potion
  - Fields: "conditions", "options" (potion id / list / tag; defaults to any potion)

4.4  minecraft:enchant_with_levels – new optional field
  - "include_additional_cost_component": boolean (default false)
  - Adds minecraft:additional_trade_cost component based on enchantment cost.

4.5  minecraft:enchant_randomly – new optional field
  - "include_additional_cost_component": boolean (default false)

4.6  minecraft:set_instrument – "options" field update
  - Now accepts a single ID or list of IDs (in addition to tag).

4.7  Removed loot entries for name tags
  - Name tag removed from loot tables for ancient_city and woodland_mansion.

SECTION 5 – PREDICATE CHANGES
================================================================================

5.1  Entity predicate – player sub-predicate: new "food" field
  - Format: { "level": {min,max}, "saturation": {min,max} }

5.2  minecraft:time_check predicate – new "clock" field
  - Specifies which world clock to use for the time check.

5.3  NEW predicate: minecraft:environment_attribute_check
  - Fields: "attribute" (environment attribute ID), "value" (exact value)
  - e.g. {condition: 'environment_attribute_check', attribute: 'gameplay/piglins_zombify', value: true}

SECTION 6 – DATA COMPONENT CHANGES
================================================================================

6.1  NEW component: minecraft:additional_trade_cost
  - Transient, used to modify item cost in villager trades; removed after trade.
  - Format: integer.

6.2  NEW component: minecraft:dye
  - Represents a dye color. Values: white, orange, magenta, light_blue, yellow,
    lime, pink, gray, light_gray, cyan, purple, blue, brown, green, red, black
  - Does NOT automatically enable functionality; item must also be in relevant tags.

6.3  minecraft:provides_banner_patterns
  - Now also accepts a single ID or list of IDs (not just a tag).

6.4  minecraft:blocks_attacks – "bypassed_by" field
  - Now also accepts a single ID or list of IDs (not just a tag).

6.5  minecraft:damage_resistant – "types" field
  - Now also accepts a single ID or list of IDs (not just a tag).

SECTION 8 – TEXT COMPONENT & NBT CHANGES
================================================================================

8.1  minecraft:nbt text component
  - When "interpret" is false, tags are now pretty-printed (not flattened).
  - "nbt" and "block" field parse failures are no longer silently ignored.
  - "entity" field no longer accepts trailing data after a selector.
  - New "plain" option: removes styling from pretty-printed text.
    ("plain" and "interpret" cannot both be true simultaneously.)

8.2  minecraft:object text component
  - New optional "fallback" field: text component used when object cannot be displayed.
  - "player" type objects (player heads) no longer usable in MotD.

8.3  minecraft:selector text component
  - "selector" field no longer accepts trailing data after a selector.

SECTION 9 – WORLD GENERATION / CONFIGURED FEATURE CHANGES
================================================================================

9.1  flower/flower_no_bonemeal/random_patch feature types REMOVED
  - Patches are now expressed using count + random_offset placement modifiers.
  - Features spawnable from bone meal are controlled by #can_spawn_from_bone_meal tag.

9.2  forest_rock configured feature RENAMED to block_blob
  - New config: "state" (block), "can_place_on" (block predicate)

9.3  ice_spike configured feature RENAMED to spike
  - New config: "state", "can_place_on", "can_replace" (block predicates)

9.4  huge_red_mushroom / huge_brown_mushroom – new parameter
  - "can_place_on": block predicate

9.5  tree feature config: force_dirt and dirt_provider REPLACED
  - Replaced by "below_trunk_provider" (rule-based block state provider)

9.6  rule_based_state_provider is now a proper block state provider sub-type
  - Can be used in any feature config that accepts a block state provider.
  - "fallback" is now optional (can be empty/absent).

9.7  count placement modifier
  - "count" field now limited to [0, 4096] (was [0, 256]).
